# 从「一张白底手办照」到「会眨眼、会看鼠标的桌宠」

> **一句话结论：先把眼睛框对、框全，顺序决定眨眼分组；素材边缘的问题放到最后再调。**
>
> 这个工具做三件事：把白底手办照片抠成透明素材、用框好的眼睛生成眨眼帧、把素材和动作参数一起交给透明桌宠窗口。
> 大多数"效果不对"的问题，都不是抠图算法的问题，而是**眼睛框的位置、顺序、组号**配错了。

**读完你会得到：**

- 一条 5 分钟能跑通的最短路径
- 每一步的按键、判定标准、常见错法
- 眨眼时间轴（眼组 / 时刻 / 闭眼时长 / 循环周期）的正确配法
- 一张「症状 → 真正原因」的速查表

## 0. 环境与依赖

| 用途 | 依赖 | 装法 |
|---|---|---|
| 图形界面、桌宠窗口 | PyQt6 | `pip install PyQt6` |
| 掩膜 / 形态学 / remap | opencv-python | `pip install opencv-python` |
| 数组与图像 IO | numpy、Pillow | `pip install numpy Pillow` |
| alpha 边缘（可选，强烈建议） | pymatting | `pip install pymatting` |

SAM 权重放在仓库的 `Punctuation_selection_of_images/sam2.1_hiera_small.pt`；缺失或加载失败时会自动回退到 GrabCut，日志里会写实际用的引擎。

```bash
# 确认 PyQt6 能起窗口（能弹出空窗口就 OK）
python3 -c "from PyQt6.QtWidgets import QApplication; a=QApplication([]); print('ok')"

# 确认源码能跑
python3 desktop_pet/launch.py --help
```

> **Wayland 提醒**：默认会话是 Wayland 时，窗口位置由合成器决定，程序没法把桌宠摆到右下角；拖动已改成系统级移动（见第 8 节）。想要完整的手感（惯性甩动、落地回弹、自由定位），用
> `QT_QPA_PLATFORM=xcb python3 desktop_pet/launch.py` 走 XWayland。

<a id="quick"></a>
## 1. 最短路径：一条命令跑通

```bash
python3 desktop_pet/launch.py          # 不带参数默认就是图形界面
```

界面里只有一条流水线，上方是步骤提示，左边是画布：

| 步骤 | 要做什么 | 完成键 |
|---|---|---|
| 1 / 4 | 框住手办 | 回车 |
| 2 / 4 | 左键打前景点、右键打背景点（可跳过） | 回车 / `s` |
| 3 / 4 | 看四联预览，决定是否返回补点 | 回车采用 / `a` 返回 |
| 4 / 4 | **逐只框眼睛**，可以框任意多只 | 回车框下一只 / `s` 完成 |

全部走完后点右侧「开始处理」，勾了「完成后启动桌宠」就会直接弹出桌宠。

**想跳过大部分步骤，最短的一条：**

```bash
python3 desktop_pet/launch.py --image photo.jpg \
  --box 120,80,900,780 \
  --eyes-boxes "150,200,320,300;400,210,560,310" \
  --no-points --no-preview
```

`--eyes-boxes` 用的是**原图坐标**，分号分隔多个框；列表顺序就是「眼1、眼2、眼3…」，第 5 节会讲为什么顺序重要。

<a id="step1"></a>
## 2. 第 1 步｜框取手办

拖拽画框，或者左键点两个对角（点完第一个角会出现黄点标记）。回车确认。

| 键 | 作用 |
|---|---|
| `r` | 清空当前框，重新画 |
| `u` | 撤销上一个点 |
| `f` | 用整张图（背景很干净时最快） |
| `ESC` | 取消整个流程 |

**两个容易踩的点：**

1. **框太大会让 SAM 把整幅图当成一个物体**。框超过半幅图时，程序会自动改成「只用点提示，框只做裁剪」。所以框只要比手办大一圈，别把整面墙都框进来。
2. **只有框内的点才算数**。补点只统计绿框里的点击，框外的点击会被忽略并提示——想让某块背景被排除，得先把框盖住它。

---

<a id="step2"></a>
## 3. 第 2 步｜补点

| 操作 | 含义 |
|---|---|
| 左键 | 前景（红叉）——这里一定是手办 |
| 右键 | 背景（蓝叉）——这里一定不是手办 |
| `r` | 清空全部点 |
| `u` | 撤销一个点 |
| `s` | 不补点，直接分割 |
| `ESC` | 取消 |

背景接近纯白时，程序直接走「非白阈值」，不加载 SAM；背景复杂时才走 SAM + 点的候选打分。日志里会打印候选分数和掩膜覆盖率，点没起作用时一眼能看出来。

**判定标准：** 预览里的白色/透明区域应该恰好包住手办，发丝和手指缝不应被吃掉。

---

<a id="step3"></a>
## 4. 第 3 步｜预览分割

上方四个单选：**叠加 / 掩膜 / 白底 / 原图+框**。

| 键 | 作用 |
|---|---|
| 回车 | 采用这份掩膜，继续框眼睛 |
| `a` | 返回第 2 步补点，重新计算 |
| `ESC` | 取消 |

**这一步只看三件事：**

1. 投影 / 地面暗边有没有被带进来（带进来就补背景点）
2. 发丝、耳尖有没有被切掉（切掉就补前景点）
3. 框边缘有没有残留白色描边（有的话后面装 `pymatting` 重跑一遍）

<a id="step4"></a>
## 5. 第 4 步｜框眼睛（决定眨眼与视线）

这一步是**整条流程里最关键的一步**：眨眼、视线跟随全靠它。

### 5.1 怎么框

- 逐只框，**每框完一只回车，就可以继续框下一只**，数量不限
- 框的是**整个眼窝**（含眼白、眼线），不要只框瞳孔
- 框完按 `s` 表示"眼睛框完了"；一只都不框 = 不眨眼也不跟随视线
- `u` 撤销：先撤当前框 → 再撤角点 → 再撤上一只已确认的眼睛
- `r` 清空当前框；`ESC` 取消整个流程

### 5.2 顺序决定分组（最重要）⭐

眼睛按**框选顺序**编号，然后**每两只一组**：

```
眼1 + 眼2  →  眼组 1  →  右侧表格的「眨眼1」
眼3 + 眼4  →  眼组 2  →  「眨眼2」
眼5 + 眼6  →  眼组 3  →  「眨眼3」
奇数只时，最后一只单独成组
```

所以想让人物双眼一起眨、猫眼另外眨，就按 **人物左眼 → 人物右眼 → 猫左眼 → 猫右眼** 的顺序框。框反了，分组就反了，桌宠会"人眨完猫才眨"，看起来像没对准。

生成时如果表格里填的眼组号超过了实际眼组数，终端会打印：

```
[warn] N 个眨眼对象的眼组超出范围（当前只有 K 组眼，桌宠会忽略）
```

看到这行说明表格组号填大了，或者眼睛框少了。

### 5.3 没有手工框眼时

`--no-eyes` 或一只都不框时，启动阶段会自动检测眼睛（靠暗色眼线找一对）。自动检测的结果会做尺寸过滤：过大的块（当成头发）和过小的碎片不参与视线跟随；手工框的眼则全部信任、全部参与。

<a id="blink"></a>
## 6. 右侧面板：眨眼时间轴

### 6.1 表格怎么填

勾选「按时间轴眨眼」后，表格三列：

| 列 | 含义 | 取值 |
|---|---|---|
| **眼组** | 哪一组眼睛眨（1 = 眼1+眼2） | ≥ 1 的整数 |
| **时刻 (s)** | 循环周期内的触发秒数 | 0 ~ 周期 - 0.01 |
| **闭眼时长 (s)** | 这次闭眼保持多久 | 0.03 ~ 3.0 |

默认给两行：**组1 @ 2.00s、组2 @ 5.00s**，循环周期 8 秒。效果就是：2 秒时人物眨眼，5 秒时猫眨眼，8 秒后从头再来——两只眼睛永远不会在同一时刻闭。

- 「新建眨眼」自动取**下一个组号**、时刻顺延 1.5 秒
- 「删除选中」「清空」按行操作
- 双击单元格直接改，非法输入会自动夹回合法范围
- 不勾「按时间轴眨眼」= 回到原来的随机眨眼

### 6.2 实现语义（也就是为什么"不同时刻"能成立）

```
u  = 已经过时间 % 循环周期
dt = u - 该对象的触发时刻（跨周期时自动回绕）
dt < 时长的一半  → 半闭
dt < 时长        → 全闭
同组多次触发重叠 → 取最近一次
```

每个眼组的眨眼帧只在本组眼睛的包围盒内改动，运行时再按组贴回自己的包围盒——所以组1 闭眼时，组2 的眼睛完全是睁着的，不会被"顺手"改成闭眼。

### 6.3 推荐配法

| 想做什么 | 配法 |
|---|---|
| 人物和宠物轮流眨 | 组1 @ 1s、组2 @ 4s，周期 6s |
| 两只眼错开一点，像真人 | 组1 @ 0.4s、组1 @ 2.6s（同一组多行，各时刻各眨一次） |
| 只想让人物眨眼 | 只留组1 的行，组2 的行删掉 |
| 眨眼太密 | 加大循环周期，或减少行数 |

<a id="output"></a>
## 7. 生成参数与产物

右上面板里能改：

| 参数 | 说明 |
|---|---|
| SKU | 素材分类目录名，决定 `assets/<sku>/` |
| 名称 | 素材文件名（stem） |
| 素材边长 | 导出 PNG 的长边像素（默认 512） |
| 显示高度 | 桌宠初始显示高度，无法超过屏幕高度的 90% |
| 引擎 / 设备 | `自动 / sam / grabcut`、`cpu / cuda` |
| 开关 | 补点、分割预览、框眼睛、完成后启动桌宠 |

生成目录结构：

```
desktop_pet/
├─ source/<sku>/<stem>_eyes.json      # 眼睛框（裁切坐标）
├─ source/<sku>/<stem>_blink.json     # 眨眼时间轴（与坐标无关）
└─ assets/<sku>/
   ├─ <stem>.png / <stem>.webp        # 透明素材
   ├─ <stem>_preview.png              # 棋盘格预览
   └─ manifest.json                   # eyes / blink / anchor / 显示高度
```

`manifest.json` 里的关键字段：

```json
{
  "stem": "xxx_pet",
  "width": 295, "height": 512,
  "anchor": {"x": 0.5, "y": 0.99},
  "display_height_px": 256,
  "eyes": [{"cx": 121.3, "cy": 89.9, "rx": 8.6, "ry": 4.8}],
  "blink": {"enabled": true, "cycle": 8.0,
            "items": [{"group": 1, "t": 2.0, "hold": 0.2},
                      {"group": 2, "t": 5.0, "hold": 0.2}]}
}
```

> 眼睛坐标会跟着裁边和缩放自动换算，所以**改了裁切框要重新生成素材**，手填坐标容易错位。
> `anchor` 是脚底中心、左上角原点，用于窗口缩放时保持"站在地面"的位置。

<a id="pet"></a>
## 8. 启动桌宠与操作

```bash
# 按 manifest 取素材和显示高度
python3 desktop_pet/pet_window.py --sku custom --stem 3b3d..._pet

# 直接指定素材 / 换高度 / 关掉眨眼或视线
python3 desktop_pet/pet_window.py --asset desktop_pet/assets/custom/xxx.png --height 320
python3 desktop_pet/pet_window.py --sku custom --no-blink --no-gaze --no-land
```

| 操作 | 效果 |
|---|---|
| 左键拖动 | 移动窗口；X11 下松手有惯性 + 落地回弹 |
| 滚轮 | 放大 / 缩小（保持脚底位置） |
| 单击 | 弹跳一下 + 连眨两下 |
| 双击 | 暂停 / 继续动画 |
| 右键菜单 | 暂停、开关眨眼/视线/落地、放大缩小、复位、退出 |

### Wayland 下为什么以前拖不动

Wayland 不允许普通客户端自己调用 `move()`，合成器会直接忽略——所以以前的按住拖是完全没反应的。现在改为越过 6px 拖动阈值后交给系统级移动（`startSystemMove()`）：

- 合成器支持 → 窗口正常跟手
- 合成器不支持 → 回退到手动移动（在 Wayland 下仍无效，建议换 `QT_QPA_PLATFORM=xcb`）

另外 Wayland 不暴露全局光标位置，视线跟随改用窗口内最近一次鼠标事件的位置，所以**鼠标移出桌宠后会停在最后的方向**，这是平台限制，不是 bug。

### 视线幅度是怎么定的

- 幅度按眼睛自身大小：约 `0.55 × 眼宽中位数`，下限 2px、上限素材短边的 2%
- 鼠标离眼睛超过屏高 3% 开始给偏移，屏高 22% 左右给满
- 逐帧 0.18s 缓动，不会一帧跳到位

觉得"看不出来"就检查两点：眼睛框是不是太小（小眼框幅度也小）、是不是刚好在眨眼窗口里（闭眼时视线暂停）。

> 当前版本**已移除头发画线与飘动功能**，右侧面板不再提供该入口；旧素材里的 `_hair.json` 保留但不生效。

## 9. 命令行 / 批量 / 无头

```bash
# 批量生成某个 SKU 的全部素材（已有 mask）
python3 desktop_pet/cutout_to_pet.py --sku bgy --size 512 --preview

# 换输出目录 / 不做 matting
python3 desktop_pet/cutout_to_pet.py --sku bgy --out-dir /tmp/pet_assets --no-matting

# 老的命令行多窗口流程
python3 desktop_pet/launch.py --cli --image photo.jpg

# 只生成、不弹桌宠
python3 desktop_pet/launch.py --image photo.jpg --no-launch

# 离线检查眨眼帧（不依赖 Qt）
python3 desktop_pet/anim.py --asset desktop_pet/assets/bgy/bgy_001_white.png \
  --preview /tmp/blink_preview.png
```

批量重生成时要记得：`_eyes.json`、`_blink.json` 放在 `source/<sku>/`，文件名和 stem 一致，否则这一条会被当成"没有眼睛标注"。

<a id="trouble"></a>
## 10. 症状速查表

| 你看到的现象 | 真正原因 | 解法 |
|---|---|---|
| 按住拖，窗口完全不动 | Wayland 忽略客户端 `move()` | 用 `QT_QPA_PLATFORM=xcb` 启动 |
| 能拖，但松手就掉回底部 | 落地回弹开启且有残余速度 | 右键菜单关「落地回弹」，或慢拖慢放 |
| 眼睛完全不跟鼠标 | 一只眼都没框 / 框太小被过滤 | 重新框整只眼窝；手工眼不受尺寸过滤 |
| 只有一部分眼睛跟鼠标 | 自动检测的异常小框被逐只过滤 | 手工框一遍眼睛 |
| 眼神幅度太小看不出 | 眼框太小，幅度按眼宽算 | 框大一点（含眼白） |
| 所有眼睛同时眨 | 表格里都填了组 1 | 按组号分行，组1 = 眼1+眼2 |
| 某个组从不眨眼 | 组号大于实际眼组数 | 看生成日志的 `[warn]`，改小或加框眼 |
| 眨眼保持时间太长/太短 | `hold` 单位是秒 | 表格里改「闭眼时长」，0.03~3.0 |
| 眨眼只在第 1 秒出现一次 | 循环周期设置太小 | 加大「循环周期」 |
| 眨眼时眼周有方块/接缝 | 眼睛框包含了眼外区域 | 重新框整个眼窝，别框到眉毛/刘海 |
| 素材边缘发白、有描边 | 缺 pymatting | `pip install pymatting` 后重跑 |
| 掩膜把投影也抠进来 | 背景点打在了投影边缘内 | 在投影上补右键点再预览 |
| 桌宠位置不在右下角 | Wayland 初始位置归合成器 | 正常现象；X11 下才会自动摆位 |
| 改完参数没变化 | 没重新生成素材 / 桌宠没重启 | 重新点「开始处理」，再重启桌宠 |
| 右侧面板被截断 | 窗口高度不足 | 参数区是可滚动区，拉大窗口或滚动它 |

<a id="accept"></a>
## 11. 验收清单与排查顺序

### 生成前

```
① 背景接近纯白吗？          → 是：可不打点
② 框是否只比手办大一圈？    → 框太大 SAM 会整幅当物体
③ 预览里发丝、指尖完整吗？  → 缺：补前景点
④ 眼睛是整只眼窝吗？        → 只框瞳孔，眨眼帧会像贴了个黑点
```

### 生成后

```
① 桌宠能启动、素材透明吗？
② 单击会跳、会连眨两下吗？
③ 时间轴模式下，各组按不同时刻眨了吗？
④ 鼠标移动，人物主眼跟着转吗？
```

### 排查顺序（照这个来，不迷路）

```
眼睛有没有框对/框全  →  分组顺序对不对  →  表格组号是否超范围
      ↓
眨眼帧是否只在眼窝内  →  视线幅度是否被眨眼窗口盖住
      ↓
拖动是否受 Wayland 限制  →  素材边缘/白边（最后再调）
```

## 附录｜manifest 自检脚本

```bash
python3 - <<'PY'
import json, pathlib
p = pathlib.Path("desktop_pet/assets/custom/manifest.json")
d = json.load(open(p))
for it in d["items"]:
```
